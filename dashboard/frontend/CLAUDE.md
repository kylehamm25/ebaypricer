# Dashboard frontend

Moved out of the root CLAUDE.md so it loads only when you are working in here.
Stack and dependencies are in `package.json`; what follows is what that file can't
tell you.

- `lib/api.ts` — API client, base URL from `VITE_API_BASE` (defaults to local backend).
- `lib/auth.tsx` / `auth-context.ts` — Supabase session provider; `App.tsx` gates all routes except `/login` behind a `Protected` wrapper.
- `lib/theme.tsx` — light/dark theme context; **components must handle both**.
- `pages/` — one file per route: Dashboard, SoldOrders, ActiveListings, ListingDetail, Lots (`/lots`, per-SKU cost/profit; a row opens LotDetail at `/lots/:sku`, which lists that lot's sold and active listings — the pencil button, not the row, opens the cost editor, shared by both as `components/shared/LotEditDialog`), Inventory (`/inventory`, the unlisted pile; a permanent card search adds a row on pick the way Valuation does, with condition/lot seed fields beside it that stamp whatever gets added next, and condition + quantity edit inline; picking a search hit adds it as the Regular print, but `components/shared/CardFinishButtons` (used here and in `InventoryEditDialog`'s own card-search step) offers small Reverse Holo/Non-Holo buttons beside every hit, plus Poke Ball/Master Ball pattern buttons for a set known to carry them (`lib/cardFinish.ts`'s `BALL_PATTERN_SETS` - currently 151, Prismatic Evolutions, Black Bolt, White Flare) - every non-regular finish appends a suffix to `card_query` (` Reverse`, ` Non Holo`, ` Poke Ball`, ` Master Ball`) that `cards.card_identity()` parses back out, so each print gets its own eBay search and comp pool (`browse_api` keeps the suffix through query truncation); the table/grid toggle is remembered per user in localStorage, and `InventoryCard` is otherwise read-only on purpose - a select and a stepper on every tile make browsing a pile a minefield of accidental edits, so the grid edits through the pencil dialog only, and inline editing stays in the table where the controls have their own columns. A select-all button and a sort dropdown sit above both views - the table has no header checkbox and its column headers cover most sort keys but not all (card number and card type have no column of their own - type isn't shown on the page at all, only sortable), so both controls are shown regardless of view rather than only where the grid's missing headers would otherwise leave no way to trigger them. Card type is the page's default sort, and is computed server-side in Python rather than in SQL - see `routers/inventory.py`'s `_sort_by_type`. The one exception is photos: a tile is also a drag-and-drop target, uploading straight to that row through the same `POST /inventory/{id}/photos` request `components/shared/PhotoUploader` uses inside the dialog (both call the shared `lib/photos.ts` helpers) - dropping needs no dialog open, but still respects `photoHostingEnabled` and shows the same per-row error a rejected upload would. `coverArt()` decides what a row's tile/thumbnail actually shows: the first `photo_urls` entry when there is one, falling back to `card_image_url` otherwise - a real photo of the card in hand beats catalog art of the printing whenever both exist; a card added from the search lands unpriced - pricing is never automatic here, including on add; a counted button prices the backlog `MAX_PRICE_BATCH` at a time, and selecting rows surfaces a second button that prices just the selection (also capped at `MAX_PRICE_BATCH`, both going through `POST /valuation/batch`) - `components/shared/InventoryEditDialog` is edit-only, for the name, cost, notes and re-picking the catalog card), PriceLog (`/log`, reads `GET /active/price-changes`), Settings (eBay OAuth connection, plus `components/shared/ListingDefaultsCard` — the item location and Seller Hub policy names the inventory listing CSV needs, saved server-side via `/settings/listing-defaults` rather than in localStorage, because they are account facts and a wrong policy name gets an upload rejected; the card also holds eBay's blank prefill template itself, uploaded through `PUT /settings/prefill-template` — that upload is the one place the frontend bypasses `lib/api.ts`, since multipart needs the browser to set its own boundary), Login. (Standalone Pricing and Promotions pages were removed; that data now lives on the Active Listings and Dashboard pages.)
- **`InventoryScanPage` (`/inventory/scan`)** is the photo intake for the unlisted pile, reached from the Inventory page. It accepts many image files at a time through file picking or drag-and-drop, sorts them by filename, and treats each consecutive pair as one card: the lower `IMG_####` number is the front and the higher is the back (an odd last file is a front-only card). It uploads one card per pair through `apiUpload` (front and back in the same request), shows the recognizer's candidate printings plus both photos, and sends the chosen one through the ordinary confirm endpoint; a clear unique match is confirmed automatically with the page's selected finish (Regular by default) and appears in a 24-hour undo list, while everything else waits for review. Condition, finish, lot and location are page-level seeds copied onto each review card, where quantity and the rest stay editable - none of it is inferred from the photo. **It never computes or fetches a price itself**: once rows exist it calls the same capped `POST /valuation/batch` the Inventory page uses, and nothing prices on load. Its banners distinguish a missing migration 0021/0022, missing Supabase photo hosting, and missing OCR packages. `CardSearch` is the shared catalog lookup extracted for this page and `InventoryEditDialog`; manual free text stays free text with no `card_query`.
- Grid views: `lib/view-preference.ts` holds `useViewPreference(page)` (remembers table-vs-grid per user **and per page** in localStorage; table is always the fallback) and `GRID_CLASS`, the one definition of column counts and gutter. `components/shared/ViewToggle` exports the toggle, `GridShell` (the tile: art full-bleed on top, details, then actions; also takes optional `onDrag*`/`onDrop`/`dropActive` pass-through props so a page can turn a tile into a drop target without GridShell knowing what is being dropped - Inventory is the one user of this so far) and `CardArt` (real card art, falling back to `components/shared/CardBack` - an inline SVG card back). **The Pokemon species sprites are gone from every card image.** They looked like data and were not: every Charizard shares one sprite, so a wrong printing and the right one were indistinguishable, and a card the matcher failed on silently showed Pikachu. A card back says "no art for this" and nothing more. `sprite_url` is still returned by several endpoints but nothing renders it. Inventory, Active Listings and Sold Orders all use these — add a grid to a new page through them, never by copying a page's tile.
- `components/shared/` — `DataTable`, `KpiCard`, `Skeleton`, `StageRefreshButton` (the page-level refresh control wired to `stage_runner`), `InventoryEditDialog` / `InventoryBulkDialog` (the latter sends only the fields you filled in, so a blank one is left alone; only condition can be cleared, because a select has room to say so and a blank text box cannot mean both things). `InventoryPrefillDialog` covers eBay's other route — it builds on open from the blank template stored on Settings, and names steps 2 and 3 of that round trip because both happen in Seller Hub and nothing else on the screen would say so. `InventoryListingCsvDialog` builds the eBay bulk-upload file for the selected rows — it asks nothing, because its settings live on Settings, but it always shows every title, price, warning and skipped row before the download; **it never computes a price or a title**, both arrive decided from `services/listing_csv.py`.
- Linting is **oxlint** (`.oxlintrc.json`), not ESLint.

## Never compute a price here

The suggested price is computed server-side and read through one API field. A
client-side `computeRecommendedPrice` used to live here and produced different
numbers on the list page than on the detail page — that is why it was deleted.
Display `suggested_price` / `suggested_price_basis`; never recompute or adjust
them in the UI. See the `ebay-pricing-rules` skill.
